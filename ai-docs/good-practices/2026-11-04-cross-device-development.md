# 跨设备功能与触摸板开发：已验证有效的方法

日期：2026-11-04。适用于 Synra 的 Rust 核心、Tauri 宿主、Vue 界面、JS 协议包及独立插件协作开发。

本次从配对、权限页、弹层和设备连接问题，推进到 Touchpad 的页面、Wasm 手势、电脑确认及 Windows 原生输入接入。
最有价值的经验，是让状态、接口、资源生命周期和验证证据相互对应。这些方法可以用于后续传输、远程动作和其他插件功能。

## 1. 先定位第一个业务错误，再处理后续界面异常

权限页打不开时，`denied is not iterable` 是直接线索；后续 `subTree`、`parentNode` 异常来自渲染中断后的组件更新。
先修复读错数据的组件及协议声明，再验证路由、详情页和其他弹层的恢复，能减少无关改动。

做法：

1. 保存用户的操作步骤、首条异常和两端日志，建立可重复的最小场景。
2. 沿调用链找到真实返回值，核对字段是否可能被省略、为空或尚未到达。
3. 修复最早破坏状态或渲染的地方，再复测后续症状。

本次 `serde` 省略空列表的行为需要同步到 TypeScript。共享 DTO 来自 `@synra/protocol`，界面按契约处理可选值，并用字段对照检查防止再次漂移。
“类型检查通过”需要建立在正确的协议声明之上。

## 2. 把双端流程写成双方可观察的状态

配对码一闪而过、接收端却已经配对，说明双方对“完成”的理解不同。
将流程逐步展开后，写入配对关系的时机、等待状态和取消职责就清楚了。

| 阶段 | 发起端 | 接收端 |
| --- | --- | --- |
| 请求到达 | 显示配对码，等待 | 显示配对码，提供同意、拒绝和拉黑 |
| 等待操作 | 可取消 | 保留当前请求 |
| 接收端同意 | 收到结果后成功 | 确认后成功 |
| 拒绝或取消 | 结束本次请求 | 结束本次请求 |

连接握手只确认通信上下文，配对关系在明确同意后写入。
对触摸板也采用同样的方法：已配对、插件已获授权、电脑允许当前控制，分别建模；手机在电脑确认之前保持等待。

可复用的原则：为每个“成功”定义双方都能确认的事实，并让界面由该事实驱动。

## 3. 沿数据的写入方和读取方排查连接问题

`lan heard` 证明收到了发现数据；能建立 TCP、已配对、在线和能够接收控制，各自还需要证据。
把这些事实分开，日志和界面才容易解释。

本次有效的检查包括：

- 核对 UDP 回包的目标地址和端口，重复查询也应得到回应。
- 区分远端声明的监听端口与入站 TCP 连接的临时源端口。
- 连接时优先采用当前有效的发现地址，给发现记录设置存活期。
- 使用设备 UUID 关联记录，显示名只用于展示。
- 发现阶段只知道 `desktop` 时保留这个事实，设备选择器识别该类型。

看到存储表或 DTO 时，同时寻找它的生产写入点、读取点和失效条件。
一张存在却没有被查询的地址表，无法改善实际拨号行为。

## 4. 把共享规则放入核心，把平台和插件职责分清

本次采用三层分工：

| 层 | 职责 |
| --- | --- |
| 插件 Vue / Rust Wasm | 页面、完整触点快照、手势识别和本插件动作 |
| 共享核心 | 输入会话、目标与权限检查、顺序、队列、租约、连接和清理 |
| 平台与宿主 | Windows 输入适配器、通用确认框、停止入口和原生页面承载 |

这样，宿主提供通用输入能力，Touchpad 保持独立插件；另一种插件也能复用相同服务。
识别手势的 Rust 代码可以独立测试，系统鼠标操作集中在平台适配器中。

扩展能力时，沿 WIT、代码生成器、SDK、宿主、CLI 校验及清单安装依次核对。
本次真实安装发现接收端权限尚未进入许可集合，因此将 `@receiver-capability` 纳入 WIT 及生成表。
接收端权限得到独立声明，发起端的导入门控继续由 `device:input` 承担。

## 5. 用所有权和生命周期处理弹层与移动端页面

同步弹层瞬间消失，同时后续抽屉失效，值得检查父组件的隐藏、卸载和布局占位。
本次将独立工作流移出会被隐藏的详情容器，统一使用 body Portal，并关闭抽屉的 push 位移。
弹层协调器只展示当前决策层，同时保留被暂时遮住的工作流和草稿。

移动端插件页面则使用独立 `PluginActivity`，在 WebView 外提供“返回 Synra”和系统返回。
导航归宿主所有，插件网页加载或执行失败时，返回入口仍然存在。

可复用的检查顺序是：谁拥有这个页面或弹层、谁决定它可见、何时卸载、关闭时释放哪些资源。
原生工程中的 Activity、Manifest 和资源也随源码管理；构建缓存、生成桥接、SDK 路径和签名配置继续忽略。

## 6. 在并发边界检查请求是否仍然有效

异步操作完成时，用户可能已经取消、切换目标或收到更新事件。
本次采用几种相互配合的做法：

- 首次读取、后续重读和事件更新使用版本票据，较早的响应不能覆盖较新的状态。
- 拨号前后重新检查取消和授权，已经取消的请求不会在连接稍后建立时弹出旧确认框。
- 每个输入会话绑定设备、目标、完整插件 id、会话 id、授权代次及严格递增序号。
- 本机停止与原生执行通过同一状态锁排序；新会话取得硬件所有权前，旧会话先完成释放。
- 多线程发布状态时序列化读取和通知，防止晚到的 Pending 覆盖 Active。

这些检查应放在产生效果的边界。页面显示一次“取消”之后，后端也必须继续遵守这个决定。

## 7. 实时输入同时设计预算与松键路径

触摸板的连续移动、点击和按住操作具有不同语义。相对移动合并时累加位移，按钮边界保持顺序；点击发生错误后结束会话。
网络工作交给独立 worker，Wasm 调用快速返回会话状态。

本次的初始预算：发送不超过 60 Hz，队列最多 64 项，每包最多 16 个操作；心跳 250 ms，接收租约 1 s，页面续租 750 ms。
这些数值是当前实现的起点，后续结合平台和负载实测调整。

释放逻辑覆盖手指抬起、取消、页面返回、失焦、后台、断连、撤权、插件停止和宿主正常退出。
接收端独立持有所按按钮并负责清理；正常退出前有界等待释放完成。

性能指标也要说明测量范围。当前 p50/p95/p99 测量 Rust 宿主入队到执行 ACK，未包含之前的页面 IPC/Wasm 排队。
跨设备单程耗时需要额外证据；本轮没有用两台设备的时钟直接相减。

## 8. 给每一层验证定义清楚的结论

| 验证 | 能够支持的结论 |
| --- | --- |
| 纯手势测试 | 接触变化、时间阈值、左右键与拖拽命令正确 |
| Vue 挂载与状态测试 | 控件、等待、取消、旧响应处理和清理正确 |
| 双端 TCP/Hello 测试 | 序号、拒绝、撤权、租约及连接结束能驱动释放 |
| 实际 `.synra` 包验收 | 文件安装、权限批准、启用、页面 nonce/RPC、Wasm 和接收服务能够连通 |
| 实体手机与电脑验收 | 对应设备上的返回体验、触控、物理鼠标效果与性能 |

完整包测试替换的是最后一层 pointer adapter，上层经过生产入口。
因此它能证明完整调用链，物理鼠标效果仍需单独验证。
本轮没有可用 adb 设备，Windows 测试窗口抓取也超时，这两项边界明确记在实施记录中。

有价值的回归用例包括：拒绝前没有原生效果、重放点击只执行一次、拖拽中撤权能释放、源页面停止续租后控制结束，以及拨号中取消不会产生晚到的请求。
跨两端的功能尽量驱动两端，等待和端口均有明确边界。

## 9. 让交付与源码版本可以复查

独立插件的 SDK 与作者 CLI 固定到同一个已审查的 core Git 提交，提交 Cargo.lock。
开发期的本地覆盖用于联调；最终固定 Git 版本后移除覆盖，再运行 locked 检查、实际组件构建和 verify。
这让跨仓库开发可以先完成验证，再进入正常发布流程。

版本控制中有两项做法值得保留：

- 开始时确认工作区基线，暂存范围明确到本轮文件；保留用户已有改动。
- 对历史格式不统一的仓库按文件格式化，审查 diff，减少无关变化。

提交前读取暂存区，实测 subject 长度，先确认检查结果，再执行签名提交并核对空 body。
GPG 解锁受阻时，继续完成可独立的实现、构建和验证；解锁后完成版本固定与提交，留下真实状态。

交付文件同样提供证据：APK 检查签名、ABI 和 Activity，EXE 检查架构，插件包走真实安装入口。
FTP 先用临时名上传，完整回读并比较 SHA-256，匹配后改为最终名，保留既有安装包。
说明文件列出两端版本和安装步骤，让使用者能直接复测。

## 下一次可以沿用的顺序

1. 保存可复现场景，画清双方状态，列出每个成功状态对应的事实。
2. 沿协议、读写方和资源所有权定位问题，确定核心、平台与插件边界。
3. 补齐取消、失效与释放路径，再连接完整用户流程。
4. 验证纯逻辑、界面、双端传输和真实包，分别记录结论与边界。
5. 固定依赖版本，审查暂存区，完成签名提交和推送。
6. 校验实际交付物，提供安装说明，并把可复用的方法记录下来。
